## Модель

`[РЕШЕНО]` Главный экран — **живая сцена**, интерфейс панелями поверх. Не менеджерский лист.
Референс подачи — Game Dev Tycoon: люди работают, состояние видно глазами, ресурсы
всплывают иконками.

`[РЕШЕНО]` Экран матча — **сцена** (команда за компами, реакция на ход матча), поверх неё три
слоя из `design/match.md`: полоса инициативы, лента моментов, таблица игроков.

`[РЕШЕНО]` Визуальный рост базы — отложен, см. `design/roadmap.md`. Сцена при этом есть с
первой версии: подвал акта 1. Отложена ветка инфраструктуры (апгрейды помещения, железо,
качество жизни), а не сцена как таковая.

## Что сцена показывает без текста

`[ЧЕРНОВИК]` Сцена несёт состояние, а не украшает:

- кто чем занят на этой неделе: тренировка, стрим, скримы, отдых
- энергия и мораль — позой и видом персонажа
- деньги, фанбаза, репутация — всплывающими иконками в момент начисления
- рост акта — сменой помещения

Правило: **любое состояние, показанное сценой, дублируется в панели числом.** Сцена создаёт
чувство, панель даёт точность. Игрок не должен щуриться, чтобы понять, устал ли Kong.

## Чем рисуется

| Слой | Чем | Почему |
|---|---|---|
| Сцена: помещение, персонажи, idle-анимации, всплывающие иконки | Pixi, спрайт-атласы | десятки анимированных спрайтов, порядок отрисовки, эффекты |
| Панели: слоты, мероприятия, «дальше», числа | DOM + CSS | текст, скролл, попадание пальцем, локализация |
| Матч: полоса инициативы, лента моментов, таблица игроков | DOM поверх сцены | строки обновляются постоянно и скроллятся |
| Таблицы: ростер, скаутинг, контракты, лиги | DOM | сортировка, фильтры, длинные списки |
| Событие с выбором | DOM-модалка + портрет-спрайт | это текст с кнопками |

## Риск №1: объём арта

Живая сцена — самая дорогая часть проекта, дороже кода. Порядок величин (оценка, не решение):
три помещения по актам, 5–12 персонажей на экране, на персонажа 4–6 состояний по несколько
кадров, плюс портреты и анимации моментов матча. Без ограничителей это тысячи кадров.

Ограничители, которые выбираются до первого спрайта:

- один скелет анимации на всех персонажей, различия — палитра и одежда
- состояние показывается позой из общего набора, а не уникальной анимацией на персонажа
- сцена фиксированного размера: без свободной камеры и без изометрии в первой версии

## Открытые вопросы

- Вид сцены: фронтальный срез помещения или изометрия. Изометрия дороже в арте кратно
- Сколько персонажей одновременно на экране в акте 3 — три отдела это 15+ человек
- Экран матча отдельный или та же сцена с наездом камеры
- Пиксельное разрешение и сетка спрайтов — фиксируется до первого арта
