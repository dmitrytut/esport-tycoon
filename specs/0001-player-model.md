# Спека 0001: модель игрока

**Статус:** сделана (`packages/core/src/performer.ts`, `generate.ts`, `observe.ts`)
**Зависит от:** —
**Дизайн-источник:** `docs/design/player.md`, `docs/design/disciplines.md` (веса статов)

## Задача

Реализовать сущность исполнителя (`Performer` в ядре, «игрок» в домене): статы, черты,
плавающее состояние, возрастная кривая, туман информации. Плюс генератор процедурных
игроков по региону и уровню.

## Вне рамок

- Матч и любые расчёты исхода (спека 0004)
- Экономика, контракты, зарплаты (спека 0005)
- Развитие через тренировки — только хранение и применение изменений, сама неделя в 0003
- Звёзды и их особые условия — только флаг редкости, поведение позже
- UI

## Модель

Шесть статов, **шкала 1–20** (решено: мелкая шкала читается на телефоне, разница в 1 пункт
ощутима игроком), домен-нейтральные ключи в ядре:

| Ключ ядра | Домен | Влияет |
|---|---|---|
| `mechanical` | Механика | исход матча |
| `cognitive` | Голова | исход матча |
| `collective` | Командность | исход матча |
| `composure` | Нервы | исход матча |
| `adaptability` | Обучаемость | адаптация к патчам, скорость роста |
| `presence` | Харизма | доход, фанбаза, пресса |

Состояние: `energy` (0–100), `morale` (0–100), `form` (−3…+3).
Шкала формы пересчитана под статы 1–20: раньше было −20…+20 при статах 1–100, то есть
±20% диапазона. Сохраняем ту же долю, а не число.
Возраст: `age`, скрытый `peakAge`, скрытый `potential`.
Черты: список ключей из `content/traits/`, 1–3 штуки.
Туман: для каждого стата хранится истинное значение и наблюдаемый диапазон;
точность зависит от качества скаутинга.

## Поведение

1. Возрастная кривая: до `peakAge` растёт `mechanical`, после — падает, `cognitive`
   растёт монотонно. Скорость роста масштабируется `adaptability` и `potential`.
2. Скрытый потенциал: пользователь никогда не видит точное число, только оценку скаута
   с ошибкой. Ошибка детерминирована сидом игрока, а не пересчитывается при каждом взгляде.
3. Черты — только объявленные модификаторы и триггеры; они не содержат логики сами,
   логика читает их по ключу.
4. Состояние меняется только через явные операции; никакой «естественной» регенерации
   вне тика недели.
5. Все случайные величины — из инжектированного RNG (`adr/0002`).

## Критерии приёмки

- [ ] игрок сериализуется и десериализуется без потери скрытых полей
- [ ] два игрока, созданные с одним сидом и одними параметрами, идентичны бит-в-бит
- [ ] оценка скаута для одного игрока стабильна между вызовами
- [ ] после 10 игровых лет `mechanical` ветерана ниже, `cognitive` выше стартовых
- [ ] ни одного киберспортивного термина в коде ядра (проходит линтер `adr/0001`)
- [ ] статы никогда не выходят за 1–20, состояние за свои границы

## Тесты

Юнит: границы, сериализация, детерминизм генератора.
Golden: снапшот 100 сгенерированных игроков при сиде 42 — ловит непреднамеренный сдвиг генератора.
